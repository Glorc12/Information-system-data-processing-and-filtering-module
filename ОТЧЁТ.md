## 4. РЕАЛИЗОВАННЫЕ API-ЭНДПОИНТЫ

### 4.1. Получение данных (GET)

**Эндпоинт:** `GET /api/v1/data`

**Назначение:** Получение всех данных из базы товаров

**Пример запроса:**
```bash
curl http://localhost:5000/api/v1/data
```

**Пример ответа:**
```json
{
  "status": "success",
  "count": 10,
  "data": [
    {
      "код": "1",
      "наименование": "Смартфон Samsung",
      "категория": "Электроника",
      "количество": "15",
      "цена": "25000"
    },
    ...
  ]
}
```

### 4.2. Передача данных (POST)

**Эндпоинт:** `POST /api/v1/data`

**Назначение:** Отправка новых данных в систему

**Пример запроса:**
```bash
curl -X POST http://localhost:5000/api/v1/data   -H "Content-Type: application/json"   -d '[{"код":"101","наименование":"Тестовый товар","категория":"Тест","количество":"5","цена":"1000"}]'
```

**Пример ответа:**
```json
{
  "status": "success",
  "message": "Сохранено 1 записей",
  "saved_to": "data/api_загруженные.csv"
}
```

### 4.3. Обработка запросов - Фильтрация (POST)

**Эндпоинт:** `POST /api/v1/filter`

**Назначение:** Фильтрация данных по различным критериям

**Поддерживаемые фильтры:**
- `категория` — фильтр по категории товара
- `наименование` — фильтр по названию
- `min_price` — минимальная цена
- `max_price` — максимальная цена

**Пример 1: Фильтр по категории**
```bash
curl -X POST http://localhost:5000/api/v1/filter   -H "Content-Type: application/json"   -d '{"категория":"Электроника"}'
```

**Пример ответа:**
```json
{
  "status": "success",
  "count": 3,
  "filters": {
    "категория": "Электроника"
  },
  "data": [
    {
      "код": "1",
      "наименование": "Смартфон Samsung",
      "категория": "Электроника",
      "количество": "15",
      "цена": "25000"
    },
    ...
  ]
}
```

**Пример 2: Фильтр по диапазону цены**
```bash
curl -X POST http://localhost:5000/api/v1/filter   -H "Content-Type: application/json"   -d '{"min_price":5000,"max_price":30000}'
```

### 4.4. Статистика (POST)

**Эндпоинт:** `POST /api/v1/stats`

**Назначение:** Расчёт статистики по данным

**Пример ответа:**
```json
{
  "status": "success",
  "stats": {
    "количество": {
      "сумма": 210,
      "среднее": 21.0,
      "минимум": 8,
      "максимум": 50,
      "записей": 10
    },
    "цена": {
      "сумма": 150000,
      "среднее": 15000.0,
      "минимум": 800,
      "максимум": 45000,
      "записей": 10
    }
  }
}
```

## 5. СТРУКТУРА ДАННЫХ

### 5.1. Формат данных

Все данные передаются в формате JSON. Обязательные поля:

| Поле | Тип | Описание |
|------|-----|----------|
| `код` | string | Уникальный код товара |
| `наименование` | string | Название товара |
| `категория` | string | Категория товара |
| `количество` | string/number | Количество на складе |
| `цена` | string/number | Цена товара в рублях |

### 5.2. Пример структуры данных

```json
{
  "код": "001",
  "наименование": "Ноутбук Dell",
  "категория": "Электроника",
  "количество": "25",
  "цена": "85000"
}
```

## 6. ОБРАБОТКА ОШИБОК

### 6.1. Коды HTTP-ответов

| Код | Описание |
|-----|----------|
| 200 | Успешный запрос |
| 201 | Данные созданы |
| 400 | Некорректный запрос |
| 404 | Ресурс не найден |
| 405 | Метод не поддерживается |
| 500 | Внутренняя ошибка сервера |

### 6.2. Формат сообщений об ошибках

```json
{
  "status": "error",
  "message": "Описание ошибки"
}
```

### 6.3. Примеры обработки ошибок

**Ошибка валидации (отсутствуют обязательные поля):**
```json
{
  "status": "error",
  "message": "Отсутствуют поля: наименование, цена"
}
```

**Ошибка формата данных:**
```json
{
  "status": "error",
  "message": "Данные должны быть массивом объектов"
}
```

**Файл не найден:**
```json
{
  "status": "error",
  "message": "Файл товары.csv не найден"
}
```
